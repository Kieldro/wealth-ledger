# wealth-ledger dashboard

Private, read-only finance dashboard: net worth, allocation, trend, accounts, holdings, cards, spending.

- **URLs:** `http://127.0.0.1:8766/` and `http://<tailscale-ip>:8766/` (the machine's Tailscale IPv4, so a phone on the tailnet can reach it). It binds only these two addresses, not the LAN or Docker bridges. `--no-tailscale` binds loopback only.
- **Service:** a systemd user unit, e.g. `~/.config/systemd/user/wealth-ledger-dashboard.service` running `.venv/bin/python dashboard/server.py --port 8766` with `Restart=on-failure`. Logs: `journalctl --user -u wealth-ledger-dashboard`.
- **Files:** `server.py` (stdlib http.server + JSON API + login), `index.html` (one page, Chart.js from cdnjs with SRI; no data leaves the machine).

## Auth
Every path needs a login, including requests from 127.0.0.1 (a Cloudflare Tunnel would connect from localhost). Only `/login`, `POST /logout`, `/robots.txt` and `/api/markets` (the sign-in page's markets line, see Live markets line) are public.
- **Login:** `/login` (show-password toggle, Caps Lock hint; a failed attempt keeps the typed username, never the password; under the card, the markets line: the latest price and daily move of a fixed list of broad benchmarks (S&P 500, gold, bitcoin), live as on the dashboard (see Live markets line), else the close in the `prices` table the sync fills (also for a ledger with no bank connected yet), the Cleveland Fed's year-over-year CPI nowcast and the time of the last fetch (both kept in the `meta` table by `insights/prices.py`), memoized; the page is public, so no other stored symbol and nothing from the ledger is ever shown). Success sets an HMAC-signed `ctd_session` cookie (HttpOnly, SameSite=Lax, 365 days, sliding: opening the page after a day re-issues it for another 365, so a device in use never gets logged out; `Secure` when the request came over HTTPS via `X-Forwarded-Proto`/`Cf-Visitor`). Sessions are also tracked server-side, so **Log out** really revokes the cookie. Unauthenticated pages redirect to `/login`; `/api/*` and `/healthz` return 401.
- **Credentials:** `~/.config/wealth-ledger/dashboard_auth.json` (must be 0600, else every login is refused): username, scrypt hash (N=2^17, r=8, p=1, random salt) and a random session-signing secret. Active sessions: `dashboard_sessions.json` in the same dir. The last successful answer to each page request is kept in `dashboard_last/` there (0600, one file per route) so the page can show the previous numbers at once while fresh ones load.
- **Set or rotate the password** (signs out every device; the running service picks it up, no restart):
  `.venv/bin/python dashboard/server.py set-password [--username NAME]` (prompts), or add `--generate` to print a random 24-letter passphrase once. Without `--username` it keeps the current one, else uses `dashboard.default_username` from personal.json.
- **Brute force:** 5 failures per client IP in 15 min, then 429 until the window clears; 50 failures in an hour from anywhere locks all logins for 15 min. Client IP = `Cf-Connecting-IP` when the request comes from loopback (cloudflared), else the socket peer. Limits live in memory: restarting the service clears a lockout (sessions survive restarts). Failed logins are logged with IP (never passwords): `journalctl --user -u wealth-ledger-dashboard | grep auth:`.
- **Headers/CSRF:** CSP (scripts limited to each page's inline-script hashes + the pinned cdnjs Chart.js on the dashboard; the sign-in page loads nothing external), `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `nosniff`, `Cache-Control: no-store`, `X-Robots-Tag: noindex`, HSTS over HTTPS. Re-read sheet (`POST /api/refresh`), Sync now (`POST /api/sync`) and logout are POST-only, and cross-site POSTs (`Sec-Fetch-Site`) are refused.

## Data
- `~/.local/share/wealth-ledger/txns.db`, opened `mode=ro`. The dashboard never writes to it; the sync does, from cron or from the page's **Sync now** (below).
- `networth.py --json` (reads the balance-sheet tab of the Google Sheet in personal.json via `gws`), cached 10 min. **Re-read sheet** (`POST /api/refresh`; **Reload** on a ledger without a sheet) re-reads the sheet only; it does not call SimpleFIN or Plaid.
- `~/.cache/wealth-ledger-status` for the last sync time and problems.

## Live markets line
The line above the totals and under the sign-in card (Bitcoin, gold, S&P 500, inflation) is the same on both pages: the stored closes, with Bitcoin, gold and the S&P 500 at live prices (`insights/live_markets.py`). Nothing else is live: net worth, allocation, trend, holdings and crypto stay at the daily run's prices, as `networth.py` prints them.
- **Sources** (free, keyless): Bitcoin from Coinbase's spot price (CoinGecko if that fails); gold at Swissquote's XAU/USD spot (`metals.spot_price`: gold-api.com, then Yahoo futures, if that fails); the S&P 500 at Yahoo's ^GSPC last trade (it moves only while the market is open).
- **Daily move:** the live price against the last stored close before the quote's trading day (Bitcoin: the UTC day, like the stored candles; gold: the COMEX trade date, a weekend being Friday's; S&P 500: the day of the last trade), so a weekend shows Friday's move, never live against an old close. Gold's move is measured on the COMEX future the stored closes are of (Yahoo GC=F), since spot and the future differ by a fraction of a percent; without it gold shows no move.
- **How often:** each source at most once a minute per server (`TTL`), however many pages are open; `/api/markets` waits at most 5 s (`WAIT`), and the page itself never waits (it shows what is already fetched, else the stored closes, and asks `/api/markets` at once). The page re-reads only the line every minute while it shows (no loading bar, nothing dimmed; a failed re-read keeps what is there) and says "Live 1:39 PM"; each price's tooltip names its source and time.
- **Fallback:** a source that fails, is slow, or answers something implausible leaves that item at its stored close; a quote older than 5 minutes is dropped. A source that starts failing is logged once to the journal; nothing is notified and nothing is written.
- **Sign-in page:** the same line, re-read the same way through `/api/markets`, which needs no session and answers only the line. Requests share the per-source cache, which asks each source at most once a minute however many visitors there are (no parameter bypasses it), and the line is built once per new set of quotes (`markets_line`), so visitors can't make the server call out or query more.
- **Off / tests:** `WEALTH_LEDGER_LIVE_MARKETS=off` turns it off (the test suite does); a path makes it read prices from that JSON file instead of the network (the browser tests' dashboard; no file = off).

## Sync now
The button starts the same sync cron runs, in the background (`POST /api/sync`), and the page follows it (`GET /api/sync`) and reloads its numbers when it ends; problems show in the page's warnings. Nothing is notified.
- **Which sync:** `bin/wealth-ledger-sync`, run with the dashboard's own environment, so an instance started with its own `WEALTH_LEDGER_*` variables syncs its own ledger. Set `WEALTH_LEDGER_SYNC_CMD` (a command line) to run a wrapper of your own instead.
- **Log:** output is appended to `WEALTH_LEDGER_SYNC_LOG` (default `~/.cache/wealth-ledger-sync.log`, the file the README's cron line writes).
- **Limits** (SimpleFIN allows about 24 requests a day across cron and the button): no sync within 15 minutes of the last one, and at most 8 from the button in any 24 hours (`SYNC_MIN_GAP_S`, `SYNC_MAX_PER_DAY` in `server.py`; the count is kept in `dashboard_sync.json` in the config dir). A sync that is already running (it holds `WEALTH_LEDGER_LOCK`) is followed, not started twice.
- **Restarts:** with systemd, the sync (and the first sync after connecting from the page) runs as a user unit of its own (`systemd-run --user`, named `wealth-ledger-sync-btn-…`), so restarting the dashboard service doesn't stop a sync under way and the page keeps following it. Without systemd (or without a user manager to talk to) it is a detached child of the dashboard, and stopping the dashboard service stops it too.

## Browser tests
`test_ui.py` drives the real page in headless Chromium (Playwright) against a throwaway dashboard on made-up data, so a change to the page can be checked without clicking through it by hand.

```sh
.venv/bin/pip install -r dashboard/requirements-test.txt && .venv/bin/playwright install chromium   # once
.venv/bin/python -m pytest -m ui             # only the browser tests (about 40 s)
.venv/bin/python -m pytest -m "not ui"       # everything else
.venv/bin/python dashboard/ui_fixture.py     # the same made-up dashboard to look at yourself (--simplefin-only for no personal.json)
```

- **What they cover:** sign-in, sign-out and the 401s; every card with its data at desktop (1280) and phone (390) widths, with no sideways scrolling and the controls reachable; loading bars and skeletons while an answer is slow; failed, refused and unanswered requests (error with Retry, and the last good numbers kept); the sync pill; Sync now (running, finished, failed, too soon, daily limit, already running, no bank connection); trend ranges and correlation chips; card reordering and folding; the hero tiles; themes, reduced motion and privacy mode; and SimpleFIN-only mode.
- **Always checked:** every test fails on an uncaught page error, a console error or warning, a failed request, an HTTP error, or a request to another host, unless the test said to expect it (`page.watch.expect(...)`).
- **Nothing real:** `ui_fixture.py` builds a synthetic ledger, `personal.json`, status file and login in a temp folder and starts `server.py` with every `WEALTH_LEDGER_*` path and `HOME` pointed there. `gws`, `systemd-run` and the sync command are stand-in scripts, so no spreadsheet, bank or price source is called, and the page's one outside file (Chart.js) is served from `testdata/` (a test checks that copy against the hash the page pins).
- **No sleeps:** a slow server is a request the test holds and releases, and the page's timers (the 20-second give-up, the 2-second sync poll) are moved with `page.clock`.
- **When one fails:** a full-page screenshot and the page's console/network log (plus the tail of the dashboard's log) are saved to `dashboard/ui-artifacts/` (git-ignored; `WEALTH_LEDGER_UI_ARTIFACTS` to put them elsewhere), and the failure report prints the paths.
- **Without Playwright or its Chromium** the browser tests skip, and the rest of the suite runs as before.
- **New controls:** give the test something stable to find (an `id`, a role and name), and add the card's telltale text to `CARD_SAYS` in `test_ui.py` when adding a card.

## API
`/api/summary`, `POST /api/refresh`, `POST /api/sync` + `GET /api/sync`, `/api/trend`, `/api/accounts`, `/api/holdings`, `/api/cards`, `/api/spending`, `/api/markets` (`{html, refresh_s}`: the markets line, see Live markets line), `/healthz`.

## Notes
- Credit cards show owed / limit and utilization per card, plus overall utilization across cards with a known limit. The limit is `v_accounts.credit_limit` (feed, or `credit_limits` in personal.json, badged `manual limit`); without one it is estimated as owed + available credit (`est.`).
- Institution icons: put a PNG at `~/.config/wealth-ledger/icons/<slug>.png`, where the slug is the institution name in lowercase with every run of other characters turned into `-` (e.g. "Test Bank, N.A." → `test-bank-n-a`). Institutions without a file show no icon.
- Categories map networth.py lines using `dashboard.exact` / `dashboard.rules` in personal.json (generic regex fallbacks in `server.py`); unknown lines fall into "Other". Sheet values are only as fresh as the last manual update and are badged `sheet`.
- Trend = daily synced snapshots (same accounts networth.py counts: no custodial accounts, crypto exchange wallets or superseded feeds) + today's sheet-only total held constant. Each point is its date's value: an account with holdings is valued at that day's market close (shares from its latest holdings snapshot on or before the date × the last close on or before it from `security_prices`, so a weekend carries Friday's; money market at $1; plus the snapshot's balance − its holdings' market values), since the feed's balances and prices arrive a day or two late. A point's `close` is the newest close used; `valued` = `{accounts, fallback: {symbol: days}}`, the symbols with no usable close (none stored, older than 7 days, or more than 2× off the feed's price), which keep the feed's price. The 1/7/30-day changes use the same values. 1/7/30-day changes show n/a until that much history exists. Before the first daily snapshot (`first_daily`), `/api/trend` also returns `sheet_points`: whole net worth (Total Equity) per dated column of the yearly balance-sheet spreadsheets, stored weekly by `insights/nw_history.py`.
- `/api/trend` also returns `prices` (`{symbol: {date: usd}}`, every series and sheet_points date, that day's close or the nearest earlier one, USD per unit) and `spot` (`{symbol: {usd, date, source}}` or null, the latest price: the `prices` table, or the valuations providers' live spot when newer) for every symbol in `insights/prices.py`: BTC, XAU/XAG/XPT (troy oz), HG (copper lb), IRR and KWD. The page's "Values in" picker shows every value in one of them at the latest price; the trend uses each day's close, except the two currencies, which use today's rate for every date.
- Benchmark overlays (trend "Compare" chips: S&P 500, Nasdaq, gold, bitcoin; off by default, remembered per browser): `/api/trend` `benchmarks` = `{dates, prices: {symbol: [usd or null per date]}, lag: {symbol: [days back to that close, or null]}}` on one date grid (weekly, daily over the last 400 days, plus every trend date) for SPX/IXIC and every unit with a price history. The page prices each benchmark in the shown unit, then rebases it to net worth at the range's first point ("if net worth had tracked it"); the legend and tooltip show each one's % change over the range. SPX/IXIC are price indexes (no dividends) and never a display unit. Each chip's correlation pairs a daily point with the benchmark's close on or before the point's `close` date (the same day), skipping points with no new close. A range that reaches back before the daily snapshots reads net worth off straight lines between the balance-sheet snapshots at the benchmark's dates (weekly beyond 120 days); its figure shows like a measured one, the method in the chip's tooltip.
- Spending = `class='spend'`, posted, since `dashboard.ledger_start`. Merchant names are lightly normalized from payee/description.
- `/api/spending` `monthly` rows also carry `income` (`class='income'`, posted: pay, rental payouts, rent, other deposits; transfers, card payments, refunds and investment moves are neither income nor spend), `n_income`, `net` (income − spend) and `partial` (this month, or the month complete data starts in mid-month). The page shows income vs spending per month and "saved $X (NN%)" for the latest full month and this month to date; partial months get no savings rate. The Rental card's payouts and expenses are a slice of these same rows, so nothing is counted twice.
- `/api/spending` `daily` = `{month: [posted spend per day, index 0 = the 1st]}` for this month (through `today`) and last month (whole month); days before `ledger_start` are null. The page draws this month's cumulative curve against last month's and compares the same day-of-month span.
- Budget vs actual: in the current month each line with money left shows left ÷ days left (today included) as "$N/day"; lines already over show nothing.
- Themes: dark only. Graphite (default), Rose, Amethyst, Plum and Sage; the swatches in the page footer switch, remembered per browser (`wl.theme` in localStorage) and applied to the sign-in page too. `"dashboard": {"theme": "rose"}` in personal.json sets a ledger's default for browsers that haven't picked one (read at start; restart the service after changing it). The palettes live in `index.html` and in `LOGIN_HTML`; keep both and `THEMES` in `server.py` in step (a test checks the names).
- Privacy mode: the eye button in the header masks every money amount and coin quantity (tables, chips, totals, chart axes and tooltips; percentages stay), remembered per browser (`wl.privacy` in localStorage). Formatters mask; a text pass also masks dollar amounts inside server-written notes, including content rendered later.
- Holdings exclude custodial accounts and blank-symbol sweeps. SimpleFIN has no cost basis. Coins at a synced crypto exchange come without a price or value; they are valued at the latest `valuations/crypto.py` run's price (the Crypto card's), and the exchange's dollar cash is not a holding.
- Port change: edit `--port` in the unit, then `systemctl --user daemon-reload && systemctl --user restart wealth-ledger-dashboard`.
